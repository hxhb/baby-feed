# 添加记录交互重设计

**日期：** 2026-08-06  
**状态：** 交互提案，待确认  
**范围：** 只定义添加记录的入口、信息架构、交互和视觉方向，不修改数据库与 API

## 1. 设计目标

添加记录是一个高频、短时、常在单手或分心状态下完成的动作。新设计应让常用记录在 2 次点击和一次数值输入内完成，同时保留疫苗、用药等低频复杂记录的完整字段。

目标：

- 不再要求用户先选择“喂养 / 健康 / 备忘”这种系统分类。
- 直接从“亲喂、奶粉、尿布、睡眠”等具体动作开始。
- 默认值来自当前时间、当前宝宝和最近一次记录。
- 只展示当前类型真正需要的字段，时间与备注按需展开。
- 典型记录无需滚动即可保存。
- 桌面与手机使用同一套信息结构，但采用不同容器。

## 2. 现状问题

当前页面功能完整，但存在以下体验问题：

1. **选择层级重复。** 用户先选择记录大类，再选择具体类型；真实意图通常直接是“记一次奶粉”或“记一次小便”。
2. **所有内容权重相同。** 类型选择、核心字段、时间、备注、错误信息分别占据大卡片，主任务不够突出。
3. **初始状态带有错误感。** 未开始输入时已出现红色字段错误、黄色提示和禁用按钮，容易让用户误以为自己操作错了。
4. **高频与低频记录采用同一表单密度。** 一次小便和一次疫苗记录的页面结构相同，没有体现任务复杂度差异。
5. **颜色和圆角过多。** 大面积渐变、分类色、阴影和多个圆角容器同时出现，削弱了视觉秩序。
6. **保存后缺少连续性。** 当前主要是跳回首页；连续补录、多次记录和撤销都不够顺手。

## 3. 核心方案：Record Composer

将独立的“添加记录页”改为全局可唤起的 **记录面板（Record Composer）**。

- 桌面端：点击顶部“记录”后，在当前页面上打开宽约 760px 的居中对话框。
- 手机端：点击底部中央“+”后，打开占屏高约 88%的底部抽屉。
- `/add?type=...` 深链接继续保留，直接打开对应记录类型。
- 面板分为“动作选择”和“记录编辑”两个状态，但在同一容器内切换，不跳整页。

### 3.1 动作选择

第一屏问题改为“刚刚发生了什么？”，直接展示用户能理解的记录动作。

```text
┌────────────────────────────────────────────────────────────┐
│ 添加记录                                乐乐 · 刚刚      × │
│ 刚刚发生了什么？                                          │
│                                                            │
│ 最近使用                                                   │
│ [亲喂  左10/右10]  [奶粉 120ml]  [小便]  [AD 已服]         │
│                                                            │
│ 喂养                                                       │
│  亲喂        瓶喂        奶粉        辅食                 │
│                                                            │
│ 日常                                                       │
│  尿布        睡眠        AD          备忘                 │
│                                                            │
│ 健康                                                       │
│  体温        体重        身高        服药        疫苗     │
└────────────────────────────────────────────────────────────┘
```

规则：

- “最近使用”最多显示 4 个动态模板，来源为该宝宝最近常用记录。
- 模板点击后只预填，不直接提交，避免误触产生错误数据。
- 分类标题只负责扫描和分组，不再作为必须点击的一级 Tab。
- 每个动作使用同一套 Lucide 线性图标；分类色只出现在图标和选中状态，不填满整块按钮。
- 多宝宝时，顶部宝宝名称可切换；单宝宝时显示为静态文本。

### 3.2 记录编辑

选择动作后，面板原地切换为专属编辑器。顶部始终可见宝宝、记录类型和“刚刚”时间入口。

```text
┌────────────────────────────────────────────────────────────┐
│ ← 亲喂                                  乐乐 · 刚刚      × │
│                                                            │
│             [ 开始计时 ]  [ 补记时长 ]                     │
│                                                            │
│ 左侧                         右侧                           │
│ [ − ]      10 分钟      [ + ]  [ − ]      10 分钟      [ + ]│
│                                                            │
│ + 添加备注                         记录时间：刚刚  >        │
│                                                            │
│                              [取消]  [保存亲喂记录]          │
└────────────────────────────────────────────────────────────┘
```

编辑器结构固定为：

1. 顶栏：返回类型选择、当前类型、宝宝、相对时间、关闭。
2. 核心区：只显示该类型的必填控件。
3. 辅助区：备注、精确时间和少用字段，默认收起或弱化。
4. 底栏：稳定的保存按钮；按钮文案不随校验状态跳变。

## 4. 各类型专属交互

| 类型 | 默认主控件 | 快捷能力 | 默认收起内容 |
|---|---|---|---|
| 亲喂 | “开始计时 / 补记时长”分段控件；左右侧独立计时或步进 | 最近左右时长；一键切换左右侧 | 精确时间、备注 |
| 瓶喂母乳 | 大号奶量输入，单位固定为 ml | 最近值、60/90/120ml | 精确时间、备注 |
| 奶粉 | 大号奶量输入，单位固定为 ml | 最近值、60/90/120/150ml | 精确时间、备注 |
| 辅食 | 辅食名称输入 | 最近食物名称；常用份量 | 份量、精确时间、备注 |
| 尿布 | 小便 / 大便 / 都有三段选择 | 默认最近类型；常见状态标签 | 自定义状态、备注、精确时间 |
| 睡眠 | “现在开始 / 补记睡眠”分段控件 | 活动中的睡眠显示“宝宝正在睡”；醒来时一键结束 | 睡眠质量、备注 |
| AD | “已服用”确认开关 | 显示今天是否已记录，避免重复 | 精确时间、备注 |
| 体温 | 数值输入，单位固定为 °C | 默认 36.5；显示合理范围 35-42 | 测量方式、备注、精确时间 |
| 体重 | 数值输入，单位固定为 kg | 显示上次值和变化，不自动预填 | 备注、精确时间 |
| 身高 | 数值输入，单位固定为 cm | 显示上次值和变化，不自动预填 | 备注、精确时间 |
| 服药 | 药物名称 + 剂量 | 最近药物模板 | 备注、精确时间 |
| 疫苗 | 未完成针次建议优先展示 | 一键带出疫苗、厂商、当前针次和总针数 | 厂商等次要字段可在选中建议后展开 |
| 备忘 | 标题 + 时间 | 最近标题不复用，时间默认当前 | 详细描述 |

说明：体重、身高等健康值只展示上次值，不自动填入，避免用户快速保存旧数据。

## 5. 计时型记录

亲喂和睡眠不是普通表单，应支持“进行中”状态。

### 亲喂计时

1. 点击“亲喂”后默认进入“补记时长”，也可切换到“实时计时”。
2. 用户点击“开始左侧”或“开始右侧”。
3. 面板可关闭，页面底部保留一条迷你计时条：`亲喂 · 左侧 08:42  [切换右侧] [完成]`。
4. 切换乳侧时暂停上一侧并开始另一侧。
5. 点击“完成”后进入预览，显示左右时长，再保存记录。

### 睡眠计时

1. 点击“睡眠”后默认进入“补记睡眠”，切换到“现在入睡”后可创建进行中状态。
2. 全局迷你条显示：`乐乐正在睡 · 1小时12分  [醒了]`。
3. 点击“醒了”补齐结束时间并展示时长确认。
4. 页面刷新或重新打开后仍能恢复进行中状态。

计时条必须有可见按钮，不依赖滑动或长按手势。

## 6. 时间与备注

- 新记录默认时间显示为相对文案“刚刚”，不占用一个完整日期输入框。
- 点击“刚刚”才展开日期时间选择器。
- 时间被修改后显示绝对时间，如“今天 14:30”；再次点击可编辑。
- 备注使用“+ 添加备注”入口，点击后在当前区域展开单行或多行输入。
- 切换记录类型时，各类型草稿分别保留；关闭有内容的面板时才提示是否放弃。

## 7. 校验与保存反馈

- 初始空白状态不显示错误。
- 数值在失焦或用户点击保存后才校验，错误紧邻对应字段。
- 保存按钮始终叫“保存XX记录”，不改成“请先补充必填信息”。
- 对可明确判断的记录允许按钮保持可用；点击后聚焦第一个错误字段。
- 保存中按钮显示进度并防止重复点击。
- 保存成功后关闭面板，显示：`已记录：奶粉 120ml · 16:47`。
- 成功提示提供“撤销”和“继续记录”；不再强制跳回首页。
- 网络失败时保留全部输入，并在面板内提供“重试”。

## 8. 响应式行为

### 手机端

- 底部抽屉宽度为屏幕宽度，高度随内容变化，最大 88dvh。
- 顶部有清晰关闭按钮，支持下拉关闭，但重要操作不依赖手势。
- 核心输入和保存按钮保持在首屏；键盘弹出时保存栏位于可视区。
- 所有点击区域至少 44×44px，动作之间至少 8px。
- 底部留出系统手势安全区。

### 桌面端

- 对话框宽 720-760px，最大高度 80vh，内部只有一个垂直滚动区域。
- 动作选择使用 4-5 列；编辑器核心区最大宽 560px，避免输入框横跨整屏。
- 点击遮罩可关闭空面板；已有输入时需要确认。
- 支持 `Esc` 关闭、`Enter` 提交单字段简单记录，并保持完整键盘焦点顺序。

## 9. 视觉方向

风格采用“安静、清楚、有温度的工具界面”，不再用大面积渐变制造重点。

- 页面背景：`#F7F8FA`
- 面板背景：`#FFFFFF`
- 主文字：`#111827`
- 次文字：`#667085`
- 边框：`#E4E7EC`
- 主操作：`#2563EB`
- 危险状态：`#D92D20`
- 圆角：面板 12px，按钮和输入框 8px，标签 999px
- 阴影：只用于浮层和进行中计时条；普通分区不加阴影
- 字体：系统中文字体栈；正文 16px，说明 14px，标题 18-20px
- 字距：保持系统默认，不使用负字距

分类色只作为定位线索：

- 母乳：玫红
- 奶瓶：蓝色
- 辅食 / 尿布：琥珀色
- 健康测量：绿色
- 睡眠：紫色
- 备忘：靛蓝色

同一屏只有“保存”一个主按钮。图标统一使用 Lucide 线性风格，选中状态通过浅色底、边框和文字共同表达，不只依赖颜色。

## 10. 动效

- 面板进入：180-220ms，上移 12px + 淡入。
- 类型切换：核心内容 160ms 交叉淡入，面板外框不跳动。
- 按压反馈：80-120ms 的背景或透明度变化，不改变布局尺寸。
- 保存成功：勾选状态 180ms，随后关闭面板并显示提示。
- 尊重 `prefers-reduced-motion`，关闭位移和缩放，仅保留状态切换。

## 11. 不采用的方案

- **不采用多步向导。** 大部分记录只有 1-2 个字段，步骤条会增加仪式感和点击次数。
- **不继续使用大类 Tab。** “喂养 / 健康”是数据模型，不是用户当下的语言。
- **不把 13 种类型塞进横向滚动条。** 隐藏在屏外的类型不易发现。
- **不让快捷模板直接提交。** 省一次点击不足以抵消误记录风险。
- **不把时间和备注永久展开。** 它们不是多数即时记录的核心信息。

## 12. 验收指标

- 奶粉、瓶喂、尿布、AD：打开面板后 2 次点击加一次数值输入内完成。
- 亲喂补记：无需滚动即可填写左右时长并保存。
- 初始界面不出现错误提示。
- 375px 宽屏幕上无横向滚动，保存按钮不被系统手势区或键盘遮挡。
- 所有类型仍覆盖现有数据字段和校验规则。
- 进行中计时在刷新、切换页面后可恢复。
- 保存失败不丢失草稿，保存成功可以撤销或继续记录。

## 13. 建议实施顺序

1. 先实现统一记录面板、直接类型选择和三种高频记录：亲喂补记、奶粉、尿布。
2. 迁移其余现有表单到面板，统一时间、备注、校验和成功反馈。
3. 增加亲喂计时、睡眠进行中状态及全局迷你条。
4. 最后加入最近模板、撤销和键盘快捷操作。
